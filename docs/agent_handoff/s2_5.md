# S2.5 Handoff Spec — Differential Steering (Switchable)

> **Read this whole document before writing any code.**
> You are implementing **Stage 2.5 only**. This is an extension of S2, not a
> replacement for S3. Safety logic (deadman timer, mode arbitration, ESTOP
> latching) remains out of scope and comes in S3.

---

## 1. Context

S2 is complete and green: the VCU subscribes to `less/v1/cmd/manual`, decodes
`DriveCommand`, and drives both L298N channels at identical speed via
`Motors::set_throttle()`. The servo path is not wired (no BEC yet) and steering
commands are currently ignored.

The physical setup is changing: a **second L298N** will drive the right-side
motor independently, enabling differential steering. The servo and Ackermann
geometry remain the future plan once a BEC is available.

This stage introduces a **`Steering` trait** so the actuator system is
switchable between differential (now) and servo-Ackermann (later) at compile
time with a one-line change in `main.rs`.

## 2. S2.5 goal

- `steer_deg` from `DriveCommand` is applied as a real speed differential
  between left and right motors, making the car visibly turn.
- All steering logic lives behind a `Steering` trait; switching to
  `ServoSteering` later requires changing **one line** in `main.rs` and nothing
  else in the control or network layer.
- `vcu/state` telemetry reflects the actual applied `steer_deg`.

### Non-goals

- No servo code. `ServoSteering` is a stub that compiles but is not wired.
- No deadman timer, no mode state machine, no ESTOP changes. Those are S3.
- No encoder feedback, no closed-loop speed control.
- No changes to `shared/`, `net/`, or `telemetry.rs` beyond the telemetry
  field fix noted in §7.

## 3. Preconditions

- S2 green (T1–T11 pass, motors respond to `throttle` commands).
- Second L298N wired:
  - Left motor: first L298N, channel A (ENA=GPIO19, IN1=GPIO21, IN2=GPIO22).
    **Unchanged from S2.**
  - Right motor: second L298N, channel A. Pin assignments below — check
    against `vcu/src/config.rs` for conflicts before wiring.
  - Both L298N GND pins tied to common ground (ESP32 GND + both L298N GNDs
    all connected).
  - Both L298N +12V from the same 12V pack.
  - ENA/ENB jumpers removed on both boards.

### New pin assignments for second L298N

Add these constants to `vcu/src/config.rs`:

| Constant | GPIO | Purpose |
|---|---|---|
| `PIN_MOTOR_R_EN` | 4 | Second L298N ENA — PWM speed, right motor |
| `PIN_MOTOR_R_IN1` | 16 | Second L298N IN1 — direction |
| `PIN_MOTOR_R_IN2` | 17 | Second L298N IN2 — direction |

> **GPIO constraints check:**
> - GPIO4: output-capable, not a strapping pin, ADC2 — but ADC2 is only
>   unavailable for *analog reads* while WiFi is active; using GPIO4 as a
>   digital PWM output is fine.
> - GPIO16/17: output-capable. On ESP32 with PSRAM these are used by PSRAM
>   SPI — if your board has PSRAM (ESP32-WROVER), use GPIO13/14/15 instead
>   and update config. Most ESP32-DevKitC boards do not have PSRAM.
>
> Verify your specific board before wiring.

## 5. The `Steering` trait

Define in `vcu/src/steering/mod.rs`:

```rust
/// The single interface the actuator task uses for all steering implementations.
/// Implementors own whatever hardware they need.
pub trait Steering: Send {
    /// Apply a drive command.
    /// steer_deg: clamped to [STEER_MIN_DEG, STEER_MAX_DEG] before this call.
    /// throttle:  clamped to [THROTTLE_MIN, THROTTLE_MAX] before this call.
    /// Both values have already been sanitised (no NaN, no infinity).
    fn apply(&mut self, steer_deg: f32, throttle: f32);

    /// Immediately bring the vehicle to a safe state:
    /// motors stopped, steering centred. Called on timeout or ESTOP.
    fn safe_state(&mut self);
}
```

This trait must be object-safe (no generics in method signatures, no associated
types used in a non-object-safe way). It will be used as `Box<dyn Steering>` in
the actuator task.

## 6. `DifferentialSteering`

Implement in `vcu/src/steering/differential.rs`.

### 6.1 Struct

Owns two independent motor channels: `left: MotorChannel` and
`right: MotorChannel`. `MotorChannel` is a refactor of the existing single-
channel concept (one EN pin + two direction pins). See §8 for the motor driver
refactor.

### 6.2 `apply()` math

```
factor      = |steer_deg| / STEER_MAX_DEG      // 0.0 at straight, 1.0 at max steer
inner_speed = throttle × (1.0 - factor)        // inside wheel slows
outer_speed = throttle                          // outside wheel unchanged

if steer_deg > 0.0:   left = inner, right = outer   // right turn
if steer_deg < 0.0:   left = outer, right = inner   // left turn
if steer_deg == 0.0:  left = throttle, right = throttle
```

Properties of this model:
- At `steer_deg = 0`: both wheels equal. Straight line.
- At `steer_deg = ±STEER_MAX_DEG` (35°): inner wheel stops (factor = 1.0,
  inner = 0). Maximum turn radius.
- At `throttle = 0`: both sides zero regardless of steer. No steering in place
  (pivot turns are S3+ if desired).
- Reverse (`throttle < 0`): both sides negative, differential preserved.
  The car steers in reverse in the physically correct direction.

### 6.3 `safe_state()`

Call `left.stop()` and `right.stop()`.

## 8. Motor driver refactor

Refactor `vcu/src/drivers/motor.rs` to expose individual channels.

### 8.1 `MotorChannel`

```rust
pub struct MotorChannel<'d> {
    en:  LedcChannel,   // PWM
    in1: Output<'d>,
    in2: Output<'d>,
}

impl<'d> MotorChannel<'d> {
    pub fn new(ledc: /* channel */, en_pin, in1_pin, in2_pin) -> Self;

    /// speed: -1.0 to 1.0. 0.0 = coast.
    pub fn set_speed(&mut self, speed: f32);

    pub fn stop(&mut self);
}
```

Direction truth table (same as S2, now per-channel):

| speed | IN1 | IN2 |
|---|---|---|
| > 0 | H | L |
| < 0 | L | H |
| = 0 | L | L |

### 8.2 Keep `Motors` for backward compatibility

Keep the existing `Motors` struct as a wrapper over two `MotorChannel`s with
`set_throttle(f32)` and `set_speeds(left: f32, right: f32)`. This avoids
breaking any S2 code paths that reference `Motors` directly and gives
`ServoSteering` something to own when it is eventually wired.

```rust
pub struct Motors<'d> {
    left:  MotorChannel<'d>,
    right: MotorChannel<'d>,
}

impl<'d> Motors<'d> {
    pub fn set_throttle(&mut self, t: f32) { self.set_speeds(t, t); }
    pub fn set_speeds(&mut self, left: f32, right: f32) {
        self.left.set_speed(left);
        self.right.set_speed(right);
    }
    pub fn stop(&mut self) { self.left.stop(); self.right.stop(); }
}
```

## 9. Actuator task changes

Modify `vcu/src/control/actuators.rs`:

```rust
#[embassy_executor::task]
pub async fn actuator_task(mut steering: Box<dyn Steering>) {
    loop {
        let cmd = RAW_CMD.wait().await;
        // Clamp again here as belt-and-suspenders (shared::clamped() already ran upstream)
        let cmd = cmd.clamped();
        steering.apply(cmd.steer_deg, cmd.throttle);

        // Update APPLIED_CMD for telemetry
        *APPLIED_CMD.lock().await = cmd;
    }
}
```

The task signature changes from `(mut servo: Servo, mut motors: Motors)` to
`(mut steering: Box<dyn Steering>)`. This is the only change to this file.

`Box<dyn Steering>` requires the global allocator. You already have
`esp-alloc` enabled from S0's `alloc` feature in `esp-generate`. If there are
any issues with `Box` in `no_std`, fall back to a generic parameter:
`actuator_task<S: Steering + 'static>(mut steering: S)` — the rest is identical.

## 12. Acceptance tests

### T1 — Builds

```bash
cd vcu && cargo build --release
```

Expect: exits 0.

### T2 — Straight ahead

```bash
mosquitto_pub -h 172.20.10.2 -t less/v1/cmd/manual \
  -m '{"steer":0.0,"throttle":0.5,"seq":1}'
```

**Expect:** both motors spin at equal speed. Car (or bench rig wheels) moves
straight. Telemetry shows `"steer":0.0,"throttle":0.5`.

### T3 — Right turn

```bash
mosquitto_pub -h 172.20.10.2 -t less/v1/cmd/manual \
  -m '{"steer":20.0,"throttle":0.5,"seq":2}'
```

**Expect:** right motor noticeably slower than left. Car arcs right. Verify by
watching the wheels — left spins faster. Telemetry shows `"steer":20.0`.

Using the math: factor = 20/35 ≈ 0.57, inner (right) = 0.5 × (1-0.57) = 0.21,
outer (left) = 0.5. Right is about 42% of left speed.

### T4 — Left turn

```bash
mosquitto_pub -h 172.20.10.2 -t less/v1/cmd/manual \
  -m '{"steer":-20.0,"throttle":0.5,"seq":3}'
```

**Expect:** left motor slower. Car arcs left. Mirror of T3.

### T5 — Maximum right turn

```bash
mosquitto_pub -h 172.20.10.2 -t less/v1/cmd/manual \
  -m '{"steer":35.0,"throttle":0.5,"seq":4}'
```

**Expect:** right motor stops (inner speed = 0), left at full throttle. Tightest
possible turn. Physically verify right wheel is not spinning.

### T6 — Reverse with steer

```bash
mosquitto_pub -h 172.20.10.2 -t less/v1/cmd/manual \
  -m '{"steer":15.0,"throttle":-0.4,"seq":5}'
```

**Expect:** both motors reverse, left motor faster (outer in reverse-right).
Car reverses while arcing right.

### T7 — Stop

```bash
mosquitto_pub -h 172.20.10.2 -t less/v1/cmd/manual \
  -m '{"steer":0.0,"throttle":0.0,"seq":6}'
```

**Expect:** both motors stop.

### T8 — Steer reflects in telemetry

While T3 command is applied:

```bash
mosquitto_sub -h 172.20.10.2 -t less/v1/vcu/state -v -C 3
```

**Expect:** `steer` field is `20.0` in the published JSON. This confirms the
telemetry fix in §11 is working.

### T9 — Compile-time switch compiles

Temporarily swap the `main.rs` active steering line to `ServoSteering::new()`,
build, then swap back:

```bash
# Edit main.rs to use ServoSteering, then:
cargo build --release
# Expect: exits 0, confirming the stub compiles cleanly
# Revert to DifferentialSteering before flashing
```

This test confirms the trait abstraction works and the one-line switch is real.

### T10 — No resets under sustained operation

Send T2 → T3 → T4 → T5 → T7 → T2 in a loop for 30 seconds. Watch serial log.

**Expect:** no `rst:0x` entries. Both L298Ns may get warm — that is normal.
Hot-to-touch means a wiring issue (both IN pins high simultaneously causing
shoot-through). Stop and recheck if that happens.
