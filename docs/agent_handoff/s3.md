## 2. S3 goal

The VCU enforces four safety invariants that must hold for the rest of the
build:

1. **Deadman timeout:** if no command arrives on the active command topic within
   `shared::CMD_TIMEOUT_MS` (300 ms), the steering system enters safe state
   immediately (motors stop, steering centres).

2. **Latched ESTOP:** once asserted (from any source), ESTOP stays asserted
   until an explicit clear message arrives. Power-cycling is not the only way
   to clear it. A timeout does NOT clear ESTOP — it is a separate condition.

3. **Absolute mode priority:** `Estop > Manual > Auto`. A command arriving on
   `cmd/auto` while in `Manual` mode is silently ignored. A command on any
   topic while ESTOP is latched is silently ignored.

4. **WiFi/broker loss triggers safe state:** already implemented via the LWT
   in S1. S3 adds the software-side equivalent: the deadman timer.

At the end of S3, switching the active mode and asserting/clearing ESTOP must
all be exercisable via `mosquitto_pub` commands documented in §11.

### Non-goals

- No joystick, no dashboard, no camera, no autonomy node.
- No `cmd/auto` subscription yet (wired in S7). The `Auto` mode variant exists
  in the state machine but the VCU need not subscribe to `cmd/auto` until S7.
  Attempting to enter `Auto` mode returns an error log and stays in current mode.
- No differential drive logic changes. The `Steering` trait is unchanged.
- No changes to `shared/`.

## 5. Runtime state (`vcu/src/state.rs`)

All cross-task shared state lives here. No business logic — only statics and
their types.

```rust
use core::sync::atomic::{AtomicBool, AtomicU32, AtomicU64};
use embassy_sync::{blocking_mutex::raw::CriticalSectionRawMutex,
                   mutex::Mutex, signal::Signal};
use shared::{DriveCommand, Mode, VcuState};

// ── Inbound ──────────────────────────────────────────────────────────────

/// Raw command from transport, before arbitration. Signal: latest wins.
pub static RAW_CMD: Signal<CriticalSectionRawMutex, DriveCommand> = Signal::new();

/// Timestamp (ms since boot) of the last message received on RAW_CMD.
/// Written by transport task, read by arbiter for deadman check.
pub static LAST_CMD_MS: AtomicU64 = AtomicU64::new(0);

/// Requested mode changes (ModeRequest from broker).
pub static MODE_REQ: Signal<CriticalSectionRawMutex, shared::ModeRequest> = Signal::new();

/// ESTOP assertion/clear commands (EstopCommand from broker).
pub static ESTOP_CMD: Signal<CriticalSectionRawMutex, shared::EstopCommand> = Signal::new();

// ── Runtime flags ─────────────────────────────────────────────────────────

/// Latched ESTOP state. true = ESTOP active. Set by arbiter only.
pub static ESTOP_LATCHED: AtomicBool = AtomicBool::new(true); // boot = safe

/// Current active mode. Use Ordering::SeqCst for reads/writes.
/// Encoding: 0=Estop, 1=Manual, 2=Auto (matches Mode::priority() inverse).
pub static ACTIVE_MODE: AtomicU32 = AtomicU32::new(0); // boot = Estop

// ── Outbound ──────────────────────────────────────────────────────────────

/// Last command applied to actuators. Read by telemetry.
pub static APPLIED_CMD: Mutex<CriticalSectionRawMutex, DriveCommand> =
    Mutex::new(DriveCommand::safe());
```

### `ACTIVE_MODE` encoding

Define a helper in `state.rs` (not in `shared` — this is VCU-internal):

```rust
pub fn mode_to_u32(m: &Mode) -> u32 {
    match m { Mode::Estop => 0, Mode::Manual => 1, Mode::Auto => 2 }
}
pub fn u32_to_mode(v: u32) -> Mode {
    match v { 1 => Mode::Manual, 2 => Mode::Auto, _ => Mode::Estop }
}
```

Use `Ordering::SeqCst` for all reads and writes to `ACTIVE_MODE` and
`ESTOP_LATCHED`. These are safety-critical flags read across tasks and
potentially across cores in later stages.

## 6. Arbiter task (`vcu/src/control/arbiter.rs`)

The arbiter is the single task that owns mode transitions and ESTOP. No other
task may write `ACTIVE_MODE` or `ESTOP_LATCHED`.

```rust
#[embassy_executor::task]
pub async fn arbiter_task()
```

### 6.1 Deadman timer

Use a `Ticker` at `CMD_TIMEOUT_MS / 2` interval (150 ms) as a poll rate. On
each tick, compute:

```rust
let now = embassy_time::Instant::now().as_millis();
let last = LAST_CMD_MS.load(Ordering::SeqCst);
let elapsed = now.saturating_sub(last);

if elapsed > CMD_TIMEOUT_MS as u64 {
    // command link silent — enter safe state
}
```

Do NOT use `Ticker::every(CMD_TIMEOUT_MS)`. That would only check once per
300 ms window, potentially allowing a 600 ms gap between last command and
detection. Polling at half the interval ensures detection within 1.5× the
timeout in the worst case.

Safe state on deadman:
- Call `steering.safe_state()` — **but see §6.4 on ownership**.
- Do not clear ESTOP or change mode. Deadman and ESTOP are independent.
- Log the event: `[WARN] arbiter: command link silent ({}ms), safe state`.

### 6.2 ESTOP handling

Poll `ESTOP_CMD.try_take()` on each ticker tick (non-blocking):

```rust
if let Some(cmd) = ESTOP_CMD.try_take() {
    if cmd.assert {
        ESTOP_LATCHED.store(true, Ordering::SeqCst);
        // safe state immediately
        defmt::warn!("ESTOP asserted by {}", cmd.source.as_str());
    } else {
        // Clear is only allowed from Manual or Estop mode, never from Auto
        let mode = u32_to_mode(ACTIVE_MODE.load(Ordering::SeqCst));
        match mode {
            Mode::Auto => defmt::warn!("ESTOP clear rejected: in Auto mode"),
            _ => {
                ESTOP_LATCHED.store(false, Ordering::SeqCst);
                defmt::info!("ESTOP cleared");
            }
        }
    }
}
```

ESTOP latch is **independent of the deadman timer.** A command arriving does
not clear ESTOP. An explicit `EstopCommand { assert: false }` is the only clear
path.

### 6.3 Mode transitions

Poll `MODE_REQ.try_take()` on each ticker tick:

```rust
if let Some(req) = MODE_REQ.try_take() {
    let current = u32_to_mode(ACTIVE_MODE.load(Ordering::SeqCst));
    let estop = ESTOP_LATCHED.load(Ordering::SeqCst);

    let allowed = match req.mode {
        Mode::Estop  => true,  // always allowed
        Mode::Manual => !estop, // allowed unless ESTOP latched
        Mode::Auto   => {
            // S7 wires this; for now, reject with a log
            defmt::warn!("Auto mode not yet available (wired in S7)");
            false
        }
    };

    if allowed {
        ACTIVE_MODE.store(mode_to_u32(&req.mode), Ordering::SeqCst);
        defmt::info!("mode -> {:?}", req.mode);
        // Publish new mode to broker (see §6.5)
    }
}
```

Priority table (from `shared::Mode::priority()`):
- `Estop` (3) always wins.
- `Manual` (2) wins over `Auto`.
- `Auto` (1) only active when no higher mode is requested and ESTOP is clear.

### 6.4 Actuator ownership problem

The arbiter needs to call `steering.safe_state()` on deadman/ESTOP, but the
actuator task also owns `steering`. They cannot both hold it.

**Resolution:** introduce a `SAFE_STATE_REQ: AtomicBool` flag in `state.rs`.
The arbiter sets it `true`; the actuator task checks it on every iteration
before applying a command, and calls `steering.safe_state()` then clears the
flag. The arbiter never touches `steering` directly.

```rust
// In state.rs:
pub static SAFE_STATE_REQ: AtomicBool = AtomicBool::new(false);

// In actuator_task (modified):
loop {
    // Check for safe-state request before waiting for next command
    if SAFE_STATE_REQ.swap(false, Ordering::SeqCst) {
        steering.safe_state();
        *APPLIED_CMD.lock().await = DriveCommand::safe();
        continue;
    }

    // Mode and ESTOP gate
    let estop = ESTOP_LATCHED.load(Ordering::SeqCst);
    let mode  = u32_to_mode(ACTIVE_MODE.load(Ordering::SeqCst));
    let in_manual = matches!(mode, Mode::Manual) && !estop;

    if !in_manual {
        // Not in operable state — wait briefly, recheck
        Timer::after(Duration::from_millis(10)).await;
        continue;
    }

    // Apply command only in Manual mode with ESTOP clear
    let cmd = RAW_CMD.wait().await;
    let cmd = cmd.clamped();
    steering.apply(cmd.steer_deg, cmd.throttle);
    *APPLIED_CMD.lock().await = cmd;
}
```

> **Note on `RAW_CMD.wait()`:** in ESTOP/wrong-mode the actuator task polls
> with a 10 ms sleep rather than blocking on `RAW_CMD.wait()`. This ensures
> the safe-state check and mode-gate checks happen promptly even when no
> commands are arriving.

### 6.5 Mode publish after transition

When a mode transition succeeds, the arbiter should signal the telemetry task
to publish the new mode immediately (rather than waiting for the next 100 ms
telemetry tick). Add a `MODE_CHANGED: AtomicBool` flag to `state.rs` for this.
Telemetry checks it on each tick and publishes immediately if set.

The arbiter also needs to trigger a `TOPIC_MODE_CURRENT` publish with retain.
Route this through the existing `TELEMETRY` signal path if `transport_task`
already handles it, or add a second signal `MODE_PUB: Signal<..., Mode>` that
`transport_task` also selects on.

## 7. Transport changes (`vcu/src/net/transport.rs`)

### 7.1 Additional subscriptions

After the existing `cmd/manual` subscription, add:

```rust
client.subscribe(shared::TOPIC_MODE_REQUEST, QoS::AtMostOnce).await?;
client.subscribe(shared::TOPIC_ESTOP,        QoS::AtLeastOnce).await?;
```

### 7.2 Upgrade to `select3` (or equivalent)

The current two-arm `select` becomes three arms:

```rust
loop {
    match select3(
        client.poll(),          // arm 1: inbound MQTT
        TELEMETRY.wait(),       // arm 2: outbound telemetry
        MODE_PUB.wait(),        // arm 3: retained mode publish
    ).await {
        Either3::First(msg)   => dispatch_inbound(msg),
        Either3::Second(state) => publish_vcu_state(&state),
        Either3::Third(mode)  => publish_mode_retained(&mode),
    }
}
```

`embassy_futures::select3` is in the `embassy-futures` crate already used.

### 7.3 `dispatch_inbound`

Route by topic:

```rust
fn dispatch_inbound(msg: MqttMessage) {
    match msg.topic {
        t if t == TOPIC_CMD_MANUAL  => handle_cmd_manual(msg.payload),
        t if t == TOPIC_MODE_REQUEST => handle_mode_request(msg.payload),
        t if t == TOPIC_ESTOP        => handle_estop(msg.payload),
        _                            => defmt::warn!("unknown topic: {}", msg.topic),
    }
}
```

`handle_cmd_manual` — same as S2.5: decode, clamp, signal `RAW_CMD`, update
`LAST_CMD_MS` with current time in ms.

`handle_mode_request` — decode `ModeRequest`, signal `MODE_REQ`.

`handle_estop` — decode `EstopCommand`, signal `ESTOP_CMD`.

All three: on decode failure, log a warning and return without panicking.

## 10. Boot sequence and arming

After flashing, the car is in ESTOP mode and will not respond to drive commands.
The operator must arm it explicitly:

```bash
# 1. Clear ESTOP
mosquitto_pub -h 172.20.10.2 -t less/v1/estop -r \
  -m '{"assert":false,"src":"operator"}'

# 2. Request Manual mode
mosquitto_pub -h 172.20.10.2 -t less/v1/mode/request \
  -m '{"mode":"MANUAL"}'

# 3. Send drive commands — now accepted
mosquitto_pub -h 172.20.10.2 -t less/v1/cmd/manual \
  -m '{"steer":0.0,"throttle":0.3,"seq":1}'
```

Add this exact sequence to `README.md` under "Boot and arming."

## 11. Acceptance tests

Run in order. Each test assumes the previous left the system in a known state.
Report actual output for each: serial log lines AND telemetry payloads.

### T1 — Builds

```bash
cd vcu && cargo build --release
```

```bash
  -m '{"steer":0.0,"throttle":0.5,"seq":2}'
```

**Expect:** after the first two publishes, `vcu/state` shows `"mode":"MANUAL",
"estop":false`. After the third, motors spin. `vcu/state` shows `throttle:0.5`.

### T4 — Deadman fires after 300 ms silence

With motors running from T3, stop publishing commands. Watch serial log.

**Expect:** within ~450 ms (300 ms timeout + up to 150 ms poll interval), the
serial log shows `[WARN] arbiter: command link silent`. Motors stop.
`vcu/state` shows `"throttle":0.0`. Mode remains `MANUAL`.

### T5 — Recovery from deadman (no re-arm needed)

Immediately after T4, send:

```bash
mosquitto_pub -h 172.20.10.2 -t less/v1/cmd/manual \
  -m '{"steer":0.0,"throttle":0.3,"seq":3}'
```

**Expect:** motors resume at 0.3 throttle without any re-arm. Deadman is a
liveness check, not a mode change. `LAST_CMD_MS` was updated and the arbiter's
next tick finds elapsed < 300 ms.

### T6 — ESTOP asserts immediately

With motors running:

```bash
mosquitto_pub -h 172.20.10.2 -t less/v1/estop -r \
  -m '{"assert":true,"src":"test"}'
```

**Expect:** motors stop within one arbiter tick (~150 ms). `vcu/state` shows
`"estop":true`. Serial: `[WARN] ESTOP asserted by test`.

### T7 — ESTOP is latched (command cannot override it)

While ESTOP is asserted from T6:

```bash
mosquitto_pub -h 172.20.10.2 -t less/v1/cmd/manual \
  -m '{"steer":0.0,"throttle":0.8,"seq":4}'
```

**Expect:** motors do NOT move. The command is silently ignored.
`vcu/state` still shows `"estop":true,"throttle":0.0`.

### T8 — ESTOP clear + re-arm

```bash
mosquitto_pub -h 172.20.10.2 -t less/v1/estop -r \

mosquitto_pub -h 172.20.10.2 -t less/v1/mode/request \
```

```bash
mosquitto_sub -h 172.20.10.2 -t less/v1/mode/current -C 1
```

### T10 — `link_ms` increments when commands stop


**Expect:** `link_ms` increases with each 100 ms telemetry tick, correctly

### T12 — Malformed payload on safety topics handled gracefully
