### How it connects

The dashboard connects to Mosquitto's **WebSocket listener on port 9001**
(already running via `infra/mosquitto.conf`). It uses MQTT.js loaded from
CDN — no build step, no npm, no framework. The iPad opens a URL served by
Python's built-in HTTP server on the Mac.

## 4. MQTT connection

```javascript
// MQTT broker is the Mac Mini's LAN IP, port 9001 (WebSocket)
// The IP is configurable via a text field in the UI so the operator
// can change it without editing code at the venue.

const client = mqtt.connect(`ws://${brokerIp}:9001`, {
    clientId: 'less-dashboard-' + Math.random().toString(16).slice(2, 8),
    keepalive: 30,
    clean: true,
    // No LWT — dashboard disconnect is not a safety event
});

client.on('connect', () => {
    client.subscribe('less/v1/vcu/state');
    client.subscribe('less/v1/vcu/status');
    client.subscribe('less/v1/mode/current');
    client.subscribe('less/v1/estop');
    updateConnectionBadge('connected');
});

client.on('offline', () => updateConnectionBadge('disconnected'));
client.on('message', (topic, payload) => dispatch(topic, payload));
```

Include a small connection panel at the top: a text input pre-filled with
`172.20.10.2`, a Connect button, and a coloured dot showing MQTT connection
state (green = connected, red = disconnected, yellow = connecting). The
operator can change the broker IP without touching code.

## 5. Touch joystick

### 5.1 Behaviour

A circular joystick rendered on a `<canvas>` element:
- Outer ring: fixed circle (the boundary), diameter ~280px on iPad.
- Inner knob: draggable circle, diameter ~100px.
- Knob snaps back to centre on touch release (touchend / mouseup).
- Knob is clamped to stay within the outer ring boundary.

X displacement → `steer_deg` (left = negative, right = positive).
Y displacement → `throttle` (up = positive/forward, down = negative/reverse).

Displacement is normalised: knob at edge = ±1.0. Scale:
```
steer_deg = (dx / max_radius) × STEER_MAX_DEG   // STEER_MAX_DEG = 35
throttle  = -(dy / max_radius)                   // negate: canvas Y is inverted
```

Clamp both to their respective ranges before publishing.

### 5.2 Publishing rate

Publish to `less/v1/cmd/manual` at **20 Hz** (every 50 ms) while a touch is
active. When touch is released and knob returns to centre, publish one final
`{"steer":0.0,"throttle":0.0,"seq":N}` then stop publishing.

**Do not publish at 50 Hz from the browser.** JavaScript timers are not
precise enough and browser tab throttling will cause bursts. 20 Hz is
sufficient — the VCU's deadman is 300 ms, so 20 Hz gives 6 commands per
deadman window.

Use a `setInterval` timer that checks whether a touch is active:

```javascript
let touchActive = false;
let seq = 0;

setInterval(() => {
    if (!touchActive && throttle === 0 && steer === 0) return;
    publishCmd(steer, throttle, seq++);
    if (!touchActive) { steer = 0; throttle = 0; } // will stop next tick
}, 50);
```

### 5.3 Mouse support

Implement both touch events (`touchstart`, `touchmove`, `touchend`) and mouse
events (`mousedown`, `mousemove`, `mouseup`) so the dashboard works on a
laptop browser during development without needing an iPad.

### 5.4 Joystick canvas drawing

Draw on each animation frame (`requestAnimationFrame`):
- Outer ring: stroke circle, colour `#334155` (dark slate), line width 3px.
- Knob: filled circle, colour changes by mode:
  - ESTOP: `#EF4444` (red)
  - MANUAL: `#3B82F6` (blue)
  - AUTO: `#10B981` (green)
  - Disconnected: `#6B7280` (grey)
- A subtle crosshair at centre for reference.
- When ESTOP is latched: knob is red and does not respond to touch
  (commands still published as 0,0 but the knob is visually frozen).

## 6. Control buttons

### 6.1 ARM button

Label: **"ARM VEHICLE"**. Large, full width of the left panel.

On tap, sends the two-message arming sequence in order with a 100 ms gap:
```javascript
// Step 1: clear ESTOP
client.publish('less/v1/estop',
    JSON.stringify({ assert: false, src: 'dashboard' }),
    { retain: true, qos: 1 });

// Step 2: request MANUAL (after 100ms)
setTimeout(() => {
    client.publish('less/v1/mode/request',
        JSON.stringify({ mode: 'MANUAL' }),
        { qos: 1 });
}, 100);
```

Button is greyed out and disabled when:
- MQTT is not connected, or
- VCU status is `offline`, or
- Mode is already `MANUAL` or `AUTO`.

### 6.2 ESTOP button

Label: **"⬛ ESTOP"**. Large, full width, red background (`#EF4444`),
white bold text.

On tap:
```javascript
client.publish('less/v1/estop',
    JSON.stringify({ assert: true, src: 'dashboard' }),
    { retain: true, qos: 1 });
```

This button is **always enabled** whenever MQTT is connected — even in AUTO
mode, even if VCU is in an unknown state. ESTOP must always be reachable.

Visual state: when `estop: true` is received in telemetry, the button pulses
(CSS animation: opacity 1.0 → 0.7 → 1.0, 1 s period) to indicate it is
latched. When `estop: false`, it is solid red with no animation.

### 6.3 Mode buttons

Two buttons side by side: **"MANUAL"** and **"AUTO"**.

MANUAL tap:
```javascript
client.publish('less/v1/mode/request',
    JSON.stringify({ mode: 'MANUAL' }), { qos: 1 });
```

AUTO tap:
```javascript
client.publish('less/v1/mode/request',
    JSON.stringify({ mode: 'AUTO' }), { qos: 1 });
```

Visual state: the active mode button is highlighted (filled background),
inactive is outlined. ESTOP mode shows neither as active — both outlined,
both dimmed. AUTO is visually available but the VCU will reject it until S7
wires it; that is acceptable and expected.

## 7. Telemetry panel

Updates on every received `less/v1/vcu/state` message. Fields:

| Display label | Source field | Format |
|---|---|---|
| Speed | `speed_mm_s` (not in VcuState — use throttle as proxy until encoders) | `throttle` × 100 displayed as "~X%" |
| Steer | `steer` | `+12.5°` or `-12.5°` |
| Throttle | `throttle` | `+0.50` |
| Link age | `link_ms` | `34 ms` — colour green <150ms, yellow 150-300ms, red >300ms |
| Uptime | `uptime_ms` | `mm:ss` format |
| Mode | `mode` | badge: ESTOP=red, MANUAL=blue, AUTO=green |
| ESTOP | `estop` | `LATCHED` in red or `CLEAR` in green |

Update rate: the VCU publishes at 10 Hz; the dashboard renders each received
message immediately. No client-side interpolation needed.

> **Note on speed:** `VcuState` currently has no `speed_mm_s` field (encoders
> are a future stage). Use `throttle` as a proxy for the demo. When encoders
> are added, this field will be replaced — note this in a code comment so S7+
> knows where to update.

## 11. Message format

All MQTT messages are JSON. Parse with `JSON.parse(payload.toString())`.
Publish with `JSON.stringify(obj)`. Use `shared`'s exact field names (from
`docs/PROTOCOL.md`) — do not invent aliases.

On parse error: log to browser console, do not update UI state. The VCU may
occasionally send a partial message during reconnection.

---

## 12. State machine in the browser

Keep a single JS state object updated by incoming MQTT messages:

```javascript
const state = {
    mqttConnected:  false,
    vcuOnline:      false,
    mode:           'ESTOP',
    estopLatched:   true,
    steer:          0.0,
    throttle:       0.0,
    linkMs:         0,
    uptimeMs:       0,
    seq:            0,
};
```

All UI rendering reads from `state`. All incoming MQTT messages update `state`
then call `render()`. This keeps the UI consistent and makes the state easy
to inspect in browser devtools during the demo.

## 13. Acceptance tests

Open on Mac first (Chrome/Safari), then on iPad. Broker must be running.
VCU does not need to be running for T1–T4.

### T1 — Serves and opens

```bash
./dashboard/serve.sh
```

Expect: terminal prints `Dashboard: http://172.20.10.X:8080`. Open that URL
in Safari on the iPad. Page loads with no console errors.

### T2 — MQTT connects to broker

With broker running, open the dashboard. The broker IP field should be
pre-filled with `172.20.10.2`. Tap Connect.

Expect: connection dot turns green. Browser console shows no errors.
Mosquitto log shows a new client connecting from the Mac's IP on port 9001.

### T3 — VCU offline state shown correctly

With VCU not running:

Expect: VCU status shows `OFFLINE`. Mode badge shows `ESTOP`. ARM button is
disabled (greyed). ESTOP button is enabled.

### T4 — ESTOP button publishes correctly

Tap the ESTOP button.

```bash
mosquitto_sub -h localhost -t 'less/v1/estop' -v
```

Expect: `less/v1/estop {"assert":true,"src":"dashboard"}` appears immediately.
The ESTOP button begins pulsing.

### T5 — ARM sequence publishes correctly

While subscribed to `less/v1/#`:

Tap ARM.

Expect: two messages in order within 200 ms:
1. `less/v1/estop {"assert":false,"src":"dashboard"}` (retained)
2. `less/v1/mode/request {"mode":"MANUAL"}`

### T6 — Joystick publishes at 20 Hz

Touch and hold the joystick knob at full forward position.

```bash
mosquitto_sub -h localhost -t 'less/v1/cmd/manual' -v
```

Expect: ~20 messages/second. `throttle` near `1.0`, `steer` near `0.0`.
Release — one final `throttle:0.0` message, then silence.

### T7 — Joystick steer direction

Drag knob right. Expect `steer` positive. Drag left. Expect `steer` negative.

### T8 — Telemetry updates with VCU running

Flash VCU, arm it (or use mosquitto_pub arming sequence). Watch dashboard.

Expect: telemetry panel updates at ~10 Hz. `uptime_ms` visibly counting up.
`mode` badge shows `MANUAL`. `link_ms` is green (<150 ms) when joystick or
mosquitto_pub is sending commands, turns red when silent >300 ms.

### T9 — ESTOP state reflected in joystick knob

With VCU running, tap ESTOP on dashboard.

Expect: joystick knob turns red. Knob does not respond to touch. VCU telemetry
shows `estop:true`. Tap ARM to recover.

### T10 — Works on iPad

Open `http://172.20.10.X:8080` in Safari on the iPad (same WiFi network).

Expect: layout renders correctly. Touch joystick works. All buttons reachable
with thumb. No horizontal scroll.

### T11 — Mode badges update

With VCU running:

```bash
mosquitto_pub -h 172.20.10.2 -t less/v1/mode/request -m '{"mode":"MANUAL"}'
```

Expect: MANUAL button highlights within one MQTT message round-trip (~100 ms).
